# F1 Data Warehouse Project - Environment Setup

This project builds a Formula 1 Data Warehouse starting from FastF1 and Ergast/Jolpica data.

The workflow extracts raw Formula 1 data, re-engineers them into reconciled CSV files, loads them into PostgreSQL, performs data quality assessment and cleaning, applies database constraints, builds derived attributes, loads the final Data Warehouse, and exports data for visualization.

---

## 1. Create and activate the Conda environment

It is recommended to use a dedicated Conda environment.

```bash
conda creatE -n f1_dw python=3.11 -y
conda activate f1_dw
```

Then upgrade `pip`:

```bash
python -m pip install --upgrade pip
```

---

## 2. Install required packages

From the project root:

```bash
pip install -r requirements.txt
```

---

## 3. PostgreSQL prerequisites

Before running the loading scripts, make sure PostgreSQL is installed and that the target databases exist.

Example:

```sql
CREATE DATABASE f1_reconciled;
CREATE DATABASE f1_dw;
```

The database connection string must be configured inside the Python scripts.

Example:

```python
DATABASE_URL = "postgresql+psycopg://postgres:rudi@localhost:5432/f1_reconciled"
```

Update username, password, host, port and database name according to your local setup.

---

## 4. Pipeline execution modes

The project can be executed in two ways:

1. **Step by step**, by running each script manually.
2. **Automatically**, by using the general pipeline runner.

The automatic runner is located in:

```text
etl_pipeline/run_pipeline.py
```

---

## 5. Step-by-step execution

### Step 1 - Extraction and re-engineering

This script extracts data from FastF1 and Ergast/Jolpica, then produces raw and reconciled CSV files.

```bash
python etl_pipeline/01_extraction_reengineering/extract_fastf1_sources.py
```

Main outputs:

```text
data/raw_api_data/
data/reconciled_csv/
```

Expected reconciled CSV files include:

```text
season.csv
circuit.csv
grand_prix.csv
session.csv
driver.csv
team.csv
result.csv
lap.csv
weather.csv
track_status.csv
```

---

### Step 2 - Load the reconciled PostgreSQL database

This script reads the reconciled CSV files and loads them into PostgreSQL.

```bash
python etl_pipeline/02_load_reconciled_db/load_reconciled_tables.py
```

Input:

```text
data/reconciled_csv/
```

Output:

```text
PostgreSQL database: f1_reconciled
```

---

### Step 3 - Data quality assessment

This script analyzes the quality of the reconciled data without modifying them.

```bash
python etl_pipeline/03_data_quality/data_quality_assessment.py
```

Typical checks include:

```text
completeness
uniqueness
validity
consistency
referential integrity
```

---

### Step 4 - Data cleaning

This script applies deterministic cleaning rules based on the data quality assessment.

```bash
python etl_pipeline/04_data_cleaning/data_cleaning.py
```

Main output:

```text
data/cleaned_csv/
```

---

### Step 5 - Apply reconciled database constraints

After data quality and cleaning, primary keys, foreign keys and unique constraints can be applied.

```bash
python etl_pipeline/05_apply_reconciled_constraints/apply_reconciled_constraints.py
```

This step validates the structural correctness of the reconciled database.

---

### Step 6 - Build derived attributes

This step creates analytical attributes needed for the Data Warehouse, such as lap context, weather context, track status categories or result-level derived attributes.

```bash
python etl_pipeline/06_derived_attributes/build_derived_attributes.py
```

Main output:

```text
data/derived_csv/
```

---

### Step 7 - Load the Data Warehouse

This script loads the final multidimensional schema into the Data Warehouse database.

```bash
python etl_pipeline/07_load_data_warehouse/load_data_warehouse.py
```

Output:

```text
PostgreSQL database: f1_dw
```

---

### Step 8 - Export data for visualization

This script exports selected warehouse tables or views into CSV files for Tableau.

```bash
python etl_pipeline/08_export_for_visualization/export_dw_to_tableau_csv.py
```

Main output:

```text
data/warehouse_exports/tableau_csv/
```

---

## 6. Run the full pipeline automatically

The whole workflow can be executed with a single command:

```bash
python etl_pipeline/run_pipeline.py
```

The runner executes each pipeline step in order and stops if one step fails.

Recommended execution order:

```text
01_extraction_reengineering
02_load_reconciled_db
03_data_quality
04_data_cleaning
05_apply_reconciled_constraints
06_derived_attributes
07_load_data_warehouse
08_export_for_visualization
```

If some scripts are not implemented yet, the runner can skip missing steps:

```bash
python etl_pipeline/run_pipeline.py --skip-missing
```

This mode is useful during development.

You can also run only part of the pipeline:

```bash
python etl_pipeline/run_pipeline.py --start-at 2 --stop-at 5
```

## 8. Database material

The `database/` folder should contain SQL scripts, schema dumps and optional backup files.

Recommended structure:

```text
database/
├── reconciled/
│   ├── schema/
│   └── dumps/
│
└── warehouse/
    ├── schema/
    └── dumps/
```

The physical PostgreSQL database folder should not be uploaded to GitHub. The database should be reproducible from scripts, CSV files and optional SQL dumps.

The FastF1 cache folder must not be uploaded to GitHub.

The following folders are generated outputs and can be regenerated by the pipeline:

```text
data/raw_api_data/
data/reconciled_csv/
data/cleaned_csv/
data/derived_csv/
data/warehouse_exports/
```

The folder `data/external/` contains manually prepared input files and should be preserved.
